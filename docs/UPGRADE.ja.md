## 5. Rust の Bot に切り替える（2026-11-28 に済み）

選ぶ環境変数 3 つだけ**です。

**切り替える前に満たしていること。**

- 本番が今の `main` の Python の Bot で動いていて、上の 1.〜3. が済んでいる（Python 側の変更と切り替えを

  DJAudio の MP3 に曲名・アーティスト・カバー画像のタグが付かなくなる

**手順。** Rust の Bot のイメージは、CI が `main` への push のたびに作って GHCR に置いています
（`ghcr.io/sukun-inu/sycs-voldemort-bot-rs`。テストが全部通った版だけ）。本番のサーバーはそれを取ってくるだけで、
Rust のコンパイルはしません。

1. 取ってこられることを確かめる。本番のサーバーで `docker pull ghcr.io/sukun-inu/sycs-voldemort-bot-rs:main` が

### 6c61884 へ戻すとき

**先に設定を書き出します。** 切り替えたあとの設定の変更は Postgres にしか無いので、
書き出さずに戻すと全部消えます。新しい版の Bot のコンテナで次を打ちます
（Portainer ならコンテナのコンソールから）。

```sh
python scripts/export_settings_to_file.py
```

今の settings.json は `settings.json.before-export-<時刻>` に退避され、Postgres の
中身で書き直されます。そのあと 6c61884 で再デプロイします（イメージも作り直す）。

- `dev_signal` 表は残りますが、6c61884 は見ないので害はありません。
- **戻す時点で表に残っている依頼は、古い Bot には拾われません。** 開発者パネルの
  「待っている依頼」が空のときに戻してください。
- ニュースの送った記事の印は 300 件まで残ったままになりますが、古い版は次の巡回で 100 件に切り直します
  （そのあとは、記事の多いフィードで送り直しがまた起きうる）。
- データベースへの変更は `dev_signal`・`bot_settings_guild`・`bot_settings_state` の
  3 つの表を足しただけです。既存の表には触っていません。古い版はどれも見ません。
- 戻したあとにもう一度上げるときは、`bot_settings_state` を消してから上げると
  settings.json から取り込み直します（消さなければ、表の中身がそのまま使われ、
  戻していた間のファイルの変更は入りません）。
