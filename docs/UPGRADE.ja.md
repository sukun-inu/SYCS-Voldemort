# 本番の上げ方

[← README.ja.md に戻る](../README.ja.md)

本番は **6c61884**（2026-11-25 時点）で動いています。この文書は、そこから今の
`main` へ上げるときに何が変わり、上げたあと何を確かめ、どう戻すかをまとめたものです。
上げるたびに、次に上げる人のために「今どの版で動いているか」を書き換えてください。

**上げたあとの確認を飛ばさないこと。** 下の 3. は、テストでは確かめられないもの
だけを集めてあります。

依存の更新の中身と理由は `requirements.txt` のコメントにあります。特に SQLAlchemy は
`SQLAlchemy[asyncio]` と書いてあることが必要です（外すと全プロセスが起動できない）。

## 2. 手順

1. **上げる前に確かめる。**
   - 開発者パネルの「待っている依頼」が空であること（念のため。残っていても Bot が移す）
   - `sycs_backup_status` が 1 で、最新のバックアップが今日のものであること
     （戻すときの拠り所になる。[BACKUP.ja.md](BACKUP.ja.md)）
2. **スタックをリポジトリから取り直し、イメージを作り直して再デプロイする。**
   Portainer の web エディタで compose だけを書き換える形にしないこと
   （リポジトリのファイルが取り直されず、Dockerfile の変更が反映されない）。
3. **Portainer の環境変数で `SETTINGS_BACKEND` を上書きしていないことを確かめる。**
   Bot と管理画面で値が食い違うと、片方の変更がもう片方に届かない。
4. **すべてのコンテナが起動したことを確かめる。** ログに
   `ImportError: The SQLAlchemy asyncio module requires that the Python 'greenlet' library is installed`
   が出ていないこと。出ていたら `requirements.txt` の `SQLAlchemy[asyncio]` が外れている。

## 3. 上げたあとに確かめること

テストでは確かめられないものだけです。

| 確かめること | どう確かめるか | 何がまずいと失敗するか |
|---|---|---|
| 3 つのアプリが生きている | `/metrics` の `sycs_up` が bot・admin・web とも 1 | 起動に失敗している |
| 管理画面からの依頼が Bot に届く | 開発者パネルでタスクを 1 つ（例: ニュース取得）実行し、Bot のログに `シグナル受信` と `シグナル完了` が出る | 表へ書けていない（管理画面が 503 を返す）か、Bot が取り出せていない |
| 残っていた依頼が移った | Bot のログに `以前の置き場（…）から N 件を表へ移しました` が出る（残りが無ければ出ない） | `以前の置き場から依頼を移せませんでした` が続くなら、`data/_dev_signals/` の権限を見る |
| 読み上げが VC で聞こえる | 読み上げを有効にしたチャンネルで発言し、Bot が VC で喋るのを聞く | davey 0.2.0 で音声暗号化（DAVE）の実装が上がった。ログに出ずに聞こえなくなりうる |
| 設定が取り込まれた | Bot か管理画面のログに `[settings] … から N ギルドを取り込みました` が 1 回だけ出て、両方に `[settings] Postgres から読み込みました（N ギルド、版 …）` が出る。N が今のサーバー数と合う | `Postgres から読み込めませんでした` が続くなら、接続先か settings.json の中身。壊れていると取り込まない |
| 管理画面の変更が Bot にすぐ届く | 管理画面で試験用のサーバーの設定を 1 つ変え、Bot の動きが数秒以内に変わる | 届かないなら、Bot と管理画面の `SETTINGS_BACKEND` が食い違っている |
| ニュースが同じ記事を送り直さない | ニュースのフィードを設定したチャンネルで、上げてからフィードの間隔の 3 回ぶんほど、同じ記事が二度並ばないこと（上げた直後の 1 回に、古い記事が数件だけ出るのは上の表のとおり） | 並び続けるなら、1 回に 300 件を超えて返すフィードがある |
| 地震アラートに画像が付く | 次に地震の通知が来たとき、震度の札と地図が付いている | Pillow 13 の変更。描き比べでは同じ結果だった（変更のコミットに記録） |

## 4. 戻し方

**先に設定を書き出します。** 切り替えたあとの設定の変更は Postgres にしか無いので、
書き出さずに戻すと全部消えます。新しい版の Bot のコンテナで次を打ちます
（Portainer ならコンテナのコンソールから）。

```sh
python scripts/export_settings_to_file.py
```

今の settings.json は `settings.json.before-export-<時刻>` に退避され、Postgres の
中身で書き直されます。そのあと 6c61884 で再デプロイします（イメージも作り直す）。

- `dev_signal` 表は残りますが、6c61884 は見ないので害はありません。
- **戻す時点で表に残っている依頼は、古い Bot には拾われません。** 開発者パネルの
  「待っている依頼」が空のときに戻してください。
- ニュースの送った記事の印は 300 件まで残ったままになりますが、古い版は次の巡回で 100 件に切り直します
  （そのあとは、記事の多いフィードで送り直しがまた起きうる）。
- データベースへの変更は `dev_signal`・`bot_settings_guild`・`bot_settings_state` の
  3 つの表を足しただけです。既存の表には触っていません。古い版はどれも見ません。
- 戻したあとにもう一度上げるときは、`bot_settings_state` を消してから上げると
  settings.json から取り込み直します（消さなければ、表の中身がそのまま使われ、
  戻していた間のファイルの変更は入りません）。
