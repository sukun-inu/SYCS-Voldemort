## 5. Rust の Bot に切り替える（2026-11-28 に済み）

Bot（`sycs-voldemort` のコンテナ）だけを、Python の Bot から Rust の Bot に入れ替えます。管理画面・Web・配信
（`/dlaudio`）は Python のままです。環境変数の名前と意味は Python と同じにしてあるので、**足すのは Bot の実装を
選ぶ環境変数 3 つだけ**です。

**切り替える前に満たしていること。**

- 本番が今の `main` の Python の Bot で動いていて、上の 1.〜3. が済んでいる（Python 側の変更と切り替えを
  同時に入れない。何かあったとき、どちらのせいか分からなくなる）
- `main` に「DJAudio のメタデータの補い（Deezer。トラッカーの B10b）」が入っている。入っていない版で切り替えると、
  DJAudio の MP3 に曲名・アーティスト・カバー画像のタグが付かなくなる

**手順。** Rust の Bot のイメージは、CI が `main` への push のたびに作って GHCR に置いています
（`ghcr.io/sukun-inu/sycs-voldemort-bot-rs`。テストが全部通った版だけ）。本番のサーバーはそれを取ってくるだけで、
Rust のコンパイルはしません。

1. 取ってこられることを確かめる。本番のサーバーで `docker pull ghcr.io/sukun-inu/sycs-voldemort-bot-rs:main` が

## 6. nginx と Rust の配信に切り替える（まだ。本人がする）

管理画面・Web の前に nginx を置き、配信（`/dlaudio/`）を Rust に入れ替えます。nginx は**ホストの同じ口（5001・8001）で受ける**ので、
Cloudflare のトンネルの設定は変えません。管理画面と Web は Python のまま（nginx の後ろに回るだけ）です。

nginx がすること:

- 管理画面（5001）: `/static/` は焼き込んだファイルを Python と同じ見出しで返す（CSS と JS は Python のイメージと同じく最小化済み）。
  `/dlaudio/` は Rust の配信へ。それ以外は Python の管理画面へ（`/metrics` も。Netdata の設定は変えない）
- Web（8001）: `/static/` は焼き込んだファイルを Python と同じ見出し・同じキャッシュの扱い（`?v=` つきは 1 年、無しは 5 分）・
  同じ圧縮で返す。それ以外は Python の Web へ
- 配信のファイル: Rust の配信がリンクを確かめて `X-Accel-Redirect` を返し、ファイルそのものは nginx が置き場から送る
  （Range・大きいファイルは nginx）。答え（期限切れ・別のサーバー・壊れた情報・ファイル名の書き方・案内のページと JSON）は
  Python と同じ（基準で確かめてある）

**切り替える前に満たしていること。**

- 本番が今の `main` の Python（管理画面・Web）で動いていて、上の 1.〜3. が済んでいる（ほかの変更と同時に入れない）
- GHCR の 2 つのイメージがログインなしで取れる。本番のサーバーで
  `docker pull ghcr.io/sukun-inu/sycs-voldemort-nginx:main` と `docker pull ghcr.io/sukun-inu/sycs-voldemort-cdn-rs:main` が通ること

### 上げたあとに確かめること（済んでいなければ）

テストでは確かめられないものだけです。

| 確かめること | どう確かめるか | 何がまずいと失敗するか |
|---|---|---|
| 3 つのアプリが生きている | `/metrics` の `sycs_up` が bot・admin・web とも 1 | 起動に失敗している |
| 管理画面からの依頼が Bot に届く | 開発者パネルでタスクを 1 つ（例: ニュース取得）実行し、Bot のログに `シグナル受信` と `シグナル完了` が出る | 表へ書けていない（管理画面が 503 を返す）か、Bot が取り出せていない |
| 残っていた依頼が移った | Bot のログに `以前の置き場（…）から N 件を表へ移しました` が出る（残りが無ければ出ない） | `以前の置き場から依頼を移せませんでした` が続くなら、`data/_dev_signals/` の権限を見る |
| 読み上げが VC で聞こえる | 読み上げを有効にしたチャンネルで発言し、Bot が VC で喋るのを聞く | davey 0.2.0 で音声暗号化（DAVE）の実装が上がった。ログに出ずに聞こえなくなりうる |
| 設定が取り込まれた | Bot か管理画面のログに `[settings] … から N ギルドを取り込みました` が 1 回だけ出て、両方に `[settings] Postgres から読み込みました（N ギルド、版 …）` が出る。N が今のサーバー数と合う | `Postgres から読み込めませんでした` が続くなら、接続先か settings.json の中身。壊れていると取り込まない |
| 管理画面の変更が Bot にすぐ届く | 管理画面で試験用のサーバーの設定を 1 つ変え、Bot の動きが数秒以内に変わる | 届かないなら、Bot と管理画面の `SETTINGS_BACKEND` が食い違っている |

| 利用者の状態の同期と修復が回っている | 起動から 20 秒ほどで、Bot のログ（カテゴリ `userstate`）に `[BOT_SETUP] user_state sync completed source=on_ready` が出る。そのあと `repair_user_state_integrity failed` が出ない | 出なければ、`BOT_BACKGROUND_WORKER` が偽になっていないか（起動の行 `[BOT] USER_STATE_SYNC_ON_READY=true: background sync task started` が出ていない）。`failed` が出るなら、その行の誤りの文を見る |

### 6c61884 へ戻すとき

**先に設定を書き出します。** 切り替えたあとの設定の変更は Postgres にしか無いので、
書き出さずに戻すと全部消えます。新しい版の Bot のコンテナで次を打ちます
（Portainer ならコンテナのコンソールから）。

```sh
python scripts/export_settings_to_file.py
```

今の settings.json は `settings.json.before-export-<時刻>` に退避され、Postgres の
中身で書き直されます。そのあと 6c61884 で再デプロイします（イメージも作り直す）。

- `dev_signal` 表は残りますが、6c61884 は見ないので害はありません。
- **戻す時点で表に残っている依頼は、古い Bot には拾われません。** 開発者パネルの
  「待っている依頼」が空のときに戻してください。
- ニュースの送った記事の印は 300 件まで残ったままになりますが、古い版は次の巡回で 100 件に切り直します
  （そのあとは、記事の多いフィードで送り直しがまた起きうる）。
- データベースへの変更は `dev_signal`・`bot_settings_guild`・`bot_settings_state` の
  3 つの表を足しただけです。既存の表には触っていません。古い版はどれも見ません。
- 戻したあとにもう一度上げるときは、`bot_settings_state` を消してから上げると
  settings.json から取り込み直します（消さなければ、表の中身がそのまま使われ、
  戻していた間のファイルの変更は入りません）。
