## 1. 機能一覧（具体）

### 1.1 金属価格コマンド
- `/metal gold` `/metal silver` `/metal platinum` `/metal all`
- JPY ベースで価格取得し、グラム指定で合計額を表示
- Embed で見やすく出力

### 1.2 AI 会話（チャンネル制御あり）
- 指定チャンネルのみ AI 応答（`/chat set` / `/chat clear`）
- ユーザーごとに会話コンテキストを保持
- モデレーション連携あり

### 1.3 監査ログ
- ログチャンネルとログレベルを設定可能（`NONE/ERROR/INFO/DEBUG`）
- 主な対象イベント:
  - メッセージ削除/編集
  - VC 参加/退出/移動
  - メンバー参加/退出
  - ニックネーム変更、ロール変更
  - タイムアウト、BAN/UNBAN

### 1.3.1 ユーザー状態監査DB（10年保持）
- `user_state_current`: 各ユーザーの最新状態（在籍/BAN/Timeout/ロール/権限）を保持
- `user_state_event`: 参加/退出、BAN/KICK、VC入退室、ロール変更などを時系列保存
- 保持期間は既定10年（`USER_STATE_RETENTION_DAYS=3650`）で、古い履歴は定期削除。
  10年は下限でもあるため、環境変数で伸ばすことはできても短くはできない
- 価格データDB（`POSTGRES_DB`）とは別DB（既定 `USER_STATE_POSTGRES_DB=user_state_audit`）で管理可能
- DB不整合時はテーブル再生成を試み、定期突合で同期ズレ（在籍/BAN/Timeout/JSON破損）を自動補正
- 管理UIの「ユーザー状態監査」アプリで検索・閲覧可能（旧URL `/admin/users/state` からも開けます）

### 1.4 ウェルカム / グッバイ
- 参加/退出時の自動メッセージ
- テンプレート変数対応: `{user}` `{username}` `{server}` `{count}`

### 1.5 VC 通知
- VC 参加/退出/移動を専用チャンネルへ通知
- 退出時は通話時間を表示
- ロールメンション通知（参加・移動時のみ。退出時はメンションしない。間隔制限あり）

### 1.6 スティッキーメッセージ
- チャンネルごとに固定メッセージを維持
- 新規投稿に追従して再掲

### 1.7 リアクションロール
- メッセージID + 絵文字ごとにロール付与/解除
- Unicode 絵文字 / カスタム絵文字対応

### 1.8 Google News フィード
- キーワード検索を定期実行して新着を投稿
- `GROQ_API_KEY` がある場合、本文を 400 文字以内で要約して添付
- フィード上限: 1サーバー最大10件
- 間隔: 5〜1440分
- 重複抑止（既出記事ハッシュ管理）

### 1.9 地震アラート（P2PQuake）
- WebSocket 常時接続で地震情報を配信
- 通知タイプの ON/OFF 切り替え:
  - `eew_forecast`, `eew_warning`, `tsunami`, `quake_info`, `bot_news`
- 最小震度フィルタ設定あり

### 1.10 DJAudio-DL
- 監視チャンネルに投稿された URL から MP3 を生成して配信リンクを送信
- 期限付き配信リンク（TTL）で提供し、期限後に自動削除
- 対応例: YouTube / SoundCloud / Bandcamp / ニコニコ動画 / TikTok / 汎用URL
- 非対応例: Spotify / Apple Music / Amazon Music
- 設定可能:
  - 監視チャンネル（URL を投稿するチャンネル）
  - 出力チャンネル（MP3 リンクを送信するチャンネル。未設定時は監視チャンネルに返信）
  - TTL
  - クールダウン
  - 1メッセージあたりのURL上限

### 1.11 TTS 読み上げ

- 指定テキストチャンネルに投稿されたメッセージを、指定 VC で自動読み上げ
- 外部 macOS TTS API（[OSX-tts.api.server](https://github.com/sukun-inu/OSX-tts.api.server)）を利用して音声合成し、FFmpeg 経由で VC 再生
- 読み上げ前の自動テキスト前処理:
  - URL → `URL`、メンション → `メンション`、チャンネルリンク → `チャンネル`、カスタム絵文字 → 絵文字名
  - 最大文字数（既定 100 文字）を超えた部分は「以下省略」に置換
- **辞書機能**: 単語 → 読み替えテキストの変換表をサーバーごとに管理
- **ユーザー個別設定**: 声の名前・速度をユーザーごとに保存
- **自動 VC 参加**: 設定済み VC に人間が入ると Bot も自動接続、全員退出で自動退出
- **タイムアウト退出**: 5 分間メッセージがなければ自動で VC から退出
- 複数メッセージはキューで順番に再生（同時再生なし）
- 設定可能:
  - 読み上げ対象テキストチャンネル（複数可）
  - Bot が入る VC チャンネル
  - サーバーデフォルトの声と速度
  - 最大読み上げ文字数

### 1.11.1 VC録音（Craig の代用）

- ボイスチャンネルの音声を**参加者ごとに別トラック**で録り、ZIP でまとめて配布
- 各トラックは同じ時間軸に揃えてあるので、そのまま重ねれば同期する
  （受信できるのは発話中のパケットだけなので、経過時間を基準に不足分を無音で埋めている）
- ZIP には各人の mp3 に加えて `info.txt` / `info.json`（チャンネル・開始者・長さ・発話時間）と、
  ミキサー用の索引 `mixer.json`（トラックの並び・波形・長さ）が入る
- 配布は DJAudio と同じトークン方式（guild 照合＋期限つき）
- **読み上げとの併用**: bot は1ギルドにつき音声接続を1本しか持てないため、
  `services/voice_session.py` で接続を共有する。録音中は占有を立て、読み上げ側の
  「VC が空になったら切る」で接続ごと落とされないようにしている
- **独立したスイッチ**: 録音と読み上げはそれぞれオン／オフでき、両方オンなら同じ接続で両方動く
- **自動録音**: 対象 VC に人が入った時点で録り始める（既定はオフ）。
  対象 VC 未指定なら読み上げの対象 VC に従う
- **停止条件**: 上限時間（既定6時間、0 で無制限）／ VC が無人 ／ `/record stop` ／
  `/tts leave` ／ Bot の停止。どの経路でも書き出してからリンクを出す
- **参加者への告知**: 開始時に対象チャンネルへ録音中である旨を必ず通知（無効化不可）。
  各自 `/record exclude` で自分を対象から外せる（進行中の録音にも即時反映）
- **ミキサー（管理画面）**: 録音を DAW のように扱える。画面は2つ
  - **アレンジ** … トラックごとの波形を共通の時間軸に並べる。途中参加は冒頭が、
    途中退出は末尾が無音になるので、「誰がいつ居たか」がそのまま見える。
    拡大・縮小（1回 1.7 倍）、波形クリックで頭出し、時間目盛りをドラッグでループ区間
  - **ミキサー** … 縦のチャンネルストリップ。dB フェーダー（3/4 の位置が 0dB という
    DAW の慣習に合わせ、目盛りも出す）、パンつまみ、レベルメーター（RMS の帯と
    ピークホールドの線、0dB の線つき）、マスターは右端に貼り付く
  - **並べ替え** … トラック名をドラッグすると順序を入れ替えられる（波形・ストリップの
    両方が追随する）。見るための並びなので画面の中だけで完結し、保存はしない
  - **区間の書き出し** … ループ区間を決めると、その範囲だけを全トラック分 ZIP で落とせる。
    無圧縮で入っている mp3 をフレーム境界で切るだけ（再エンコードしない）ので速く、
    音も劣化しない。切り出しても時間軸は揃ったまま
  - **声の解析** … トラックの「?」から、その声に加工が入っていないかを調べる
    - **時間目盛りをドラッグして区間を選んでから押す。** その区間だけを調べる。
      区間を選ばないと録音全体から少しずつ抜き出すことになり、長い録音では
      ほとんど当たらない（4時間22分の実録音5本では、5本とも判定不能になった）。
      どこを見るかは波形を見ている人がいちばん確かに分かる
    - フォルマントの間隔から声道長を求める（Fitch の formant dispersion）。
      人の声道はおよそ 10〜19cm で、そこを外れる値や、声の高さと食い違う値が出たら
      加工の形跡とみなす
    - 結果には「調べた区間」と、**その区間の中で値がどこまで散らばっていたか**を
      併記する。散らばりが判定の境目をまたぐときは「加工の形跡あり」とは言わず、
      選び直しを促す（中央値がどちら側へ落ちるかがたまたまで決まるため）
    - 単純な変換（リサンプリング方式）なら倍率を推定し、打ち消して聞ける。
      **打ち消す倍率は耳で合わせる**（本人の地声が分からない以上、正しい倍率を
      機械が決めることはできない）
    - **できないこと**: 話者の同定。RVC のように声質を別人のモデルへ置き換える
      方式からの復元（元話者の声道特性は変換ではなく破棄されるため、逆関数が無い）。
      人の範囲に着地する程度の変換（大柄な人の声を1.35倍すると、小柄な人の実測値と
      区別がつかない）。**同じ人でも選ぶ区間によって判定が割れることがある**ので、
      1つの区間の結果だけで結論を出さないこと
  - キーボード: スペースで再生／停止、←→ で移動（Shift で10秒）、Home で先頭、＋− で拡大
  - 波形は**表示している範囲だけ**描く。6時間を 40px/秒 で並べると 86万px になり、
    キャンバスの幅の上限（32767px 前後）を超えるため
  - 波形の目盛りは点数が増えすぎないよう間引く（上限 3000 点）。**間引き幅は
    全トラックで1つに揃え、間引いたあとの「1点＝何秒か」を索引に書く**。
    トラックごとに間引き幅を決めて索引には間引く前の値を書いていたときは、
    12.5分を超える録音で波形が時間軸の先頭へ圧縮されていた（6時間なら全体が
    先頭12.4分ぶんに潰れる）。短く終わったトラックは末尾を無音で揃える
  - 全トラックを同時に鳴らし、最初のトラックを基準に追従させる。基準は
    並べ替えても入れ替わらない（入れ替わると再生位置が別の時計へ飛ぶ）。
    小さなずれは**再生速度をわずかに変えて**吸収し、頭出しのやり直しは
    0.75秒を超えたときだけにする（頭出しは音が途切れるため、細かいずれの
    たびにやると鳴り直しになる）
  - 頭出しと再生の前に、全トラックのメタデータが読めるまで待つ。読み込めて
    いない `<audio>` は `currentTime` への代入を黙って捨てるため、待たずに
    鳴らすとそのトラックだけ 0 秒から始まる
  - `python tools/check_recording_mixer.py` で、波形の縮尺と再生位置の一致を
    実ブラウザで確かめられる
  - 数時間×人数ぶんを丸ごとメモリへ展開せずに済むよう、`<audio>` のストリーミング再生に
    Web Audio の GainNode を挟む構成にしている。ZIP 内の mp3 は**無圧縮**で格納し、
    展開せずに Range リクエストで途中から読めるようにしてある
- **E2EE（DAVE）対応**: Discord は 2024年9月から音声を端から端まで暗号化しており、
  2026年3月2日からボットにも必須（未対応だと音声接続がクローズコード 4017 で拒否される）
  - 鍵交換（MLS）は discord.py 2.7.1 が実装済みで、`davey` が入っていれば自動で成立する。
    ただし discord.py が使うのは**送信側だけ**で、受信側の復号はどこにも無い
    （discord-ext-voice-recv にも無い）。そこを `services/dave.py` で補う
  - フレーム末尾のマーカー（`0xFAFA`）と補助データ長で暗号化フレームを見分け、
    `DaveSession.decrypt()` で平文の Opus に戻してから録る
  - 判定は補助データ長まで確認する（偶然 `0xFAFA` が並んだ平文を誤判定しないため）。
    RTP パディングが剥がされずに残っている場合があるので、末尾から少しさかのぼって探す
  - 復号できないときは、暗号文を Opus に渡さない。渡すと例外にならず**雑音が返る**ため、
    「録れているのに聞けない」という壊れ方になる。割合が高ければ理由を添えて停止する
- **RTP のパディングを取り除く**: voice_recv は剥がさない（`rtp.py` に「discord は
  このビットを使っていないようだ」とあるが、実際には使われている）。帯域推定のための
  探査パケット（中身が全部パディング）が届き、Opus に渡すと「壊れている」と言われる。
  本番では 247バイト全部 `0xF7`／255バイト全部 `0xFF` として観測した（最終バイトが
  パディング長を表し、全体の長さと一致する＝音声は1バイトも入っていない）
- 取りこぼした音声パケットがあれば数を記録し、結果に添える
- **書き出した音の自動確認**: 長さもトラック数も正しいのに中身が雑音、という
  壊れ方をしたため、書き出し時に各トラックの周期性（自己相関の山の高さ）を測る。
  声は準周期的なので山が立ち、雑音では立たない（実測: 正常 0.51 / 白色雑音 0.17）。
  下回ったトラックは Discord の結果とミキサーの両方に印を付ける
  - 長さに依らず一定のコストで測るため、録音の各所から 8 箇所だけ抜き出す
  - `python tools/check_recording_audio.py <mp3>` で手元の録音も測れる
- 音声受信は discord.py 本体に無いため `discord-ext-voice-recv` を使用。
  入っていない環境では読み上げは通常どおり動き、録音だけが理由付きで断られる
- **受信パケットの組み立て**: 拡張のジッタバッファは、順番待ちの穴が空いた瞬間に
  バッファ全体を捨てて1つだけ返す（router 側が `timeout=0` で pop するため）。
  大量に落ちるうえ順不同で出てくるので、そのまま Opus に渡すと音が壊れる。
  そのため受信側でもう一度並べ直してから復号している
  - デコーダは **SSRC ごと**に持つ（Opus は直前の状態を使って復号するので、
    別ストリームを1つのデコーダに入れると音が壊れる）
  - 位置合わせは到着時刻ではなく **RTP タイムスタンプ**（48kHz 刻み）で行う。
    到着時刻で置くと、ジッタのぶんだけ無音が挟まって時間軸が歪む
  - 落ちたフレームは Opus の欠落補間に任せる（黙って飛ばすと継ぎ目が濁る）

> 音声は個人情報保護法上の個人情報に該当し得ます。運用は各サーバーの責任において
> 法令に則って行ってください。運営者は政府機関への提供が必要な場合を除き録音データを使用しません。
> 詳細は[プライバシーポリシー](../webapp_admin/templates/privacy.html)を参照してください。

### 1.12 セキュリティ検知
- スパム判定
- Unicode トリック検知
- VirusTotal URL/添付スキャン
- GPT モデレーション
- **バイパス判定に失敗したときは強制措置を行わない** — 信頼済みユーザー／
  バイパスロールの設定を読めなかった場合、「バイパスなし」とはみなさず、
  メッセージ削除・全ロール剥奪を見送ってログチャンネルへ「要確認」を出す。
  ロール剥奪は元に戻せないため、見逃すより取り返しがつかないほうを避ける
- VC レイド検知
- 信頼済みユーザー / バイパスロールによる除外設定

### 1.15 機能と管理導線（早見表）

管理 UI 側の URL は、開くとデスクトップ上の該当ウィンドウが立ち上がります
（`/admin/overview#tts` のようにハッシュでも同じ画面を直接開けます）。

| 機能 | Discord 側 | 管理 UI 側 |
|---|---|---|
| ログ / AI 応答チャンネル | `/log channel` `/log level` `/chat set` `/chat clear` | `/admin/settings/logging` |

| VC 通知 | `/vcnotify set` `/vcnotify clear` | `/admin/settings/vc-notify` |
| スティッキー | `/sticky set` `/sticky clear` `/sticky list` | `/admin/settings/sticky` |
