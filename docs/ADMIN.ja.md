## 1. 使い方

1. `/admin` にアクセス
2. Discord OAuth でログイン
3. 管理するサーバーを選択
4. 左下の **スタート** から設定画面（アプリ）を開く

管理画面はデスクトップ風の1画面で、各設定はその上のウィンドウとして開きます。
ウィンドウはタイトルバーで移動、右下の隅でリサイズでき、位置と開いていたアプリは
ブラウザに保存されて次回そのまま復元されます。

- 設定の変更は **明示保存** です。変更すると保存バーの「保存」が有効になり、
  押すまで反映されません。未保存のまま閉じようとすると確認が出ます。
- 一覧への **追加・削除は即時反映** です（保存ボタンには含まれません）。
- `#tts` のようにURLの末尾を付けると、そのアプリを開いた状態で始まります。
  旧URL（`/admin/settings/tts` など）にアクセスした場合も同じ画面へ転送します。

## 2.1 SQL エディタ（開発者専用）

pgAdmin を別に立てずに Postgres を見て触るための画面です。`DEV_USER_ID` に一致する
ユーザーだけに出ます（それ以外にはタイルも API も存在しません）。

**接続先** — アプリが持っている DSN（`POSTGRES_*` と `USER_STATE_POSTGRES_*`）だけを使います。
画面からホストや資格情報を指定することはできません。切り替えられるのは、そのサーバ上の
**データベース名**だけです（`pg_database` から一覧します）。

**安全側の既定**

| 仕組み | 内容 |
|---|---|
| 読み取り専用 | 既定は Postgres の `READ ONLY` トランザクション。SQL の文字列判定ではないので抜け道が無い |
| 書き込み | 明示的に「書き込み」へ切り替えたときだけ COMMIT する。切り替えのたびに確認が出る。画面を開き直すと読み取り専用へ戻る |
| 制限時間 | `statement_timeout`（既定 15 秒 / 最大 120 秒） |
| 行数 | サーバ側カーソルで上限まで（既定 500 行 / 最大 5000 行）しか取り出さない |
| 接続 | 実行ごとに専用接続を開いて閉じる。アプリ本体のコネクションプールを奪わない |
| 記録 | 実行した SQL は誰が投げたかと併せて `admin.log` に残る |
| 例外 | `VACUUM` / `CREATE DATABASE` / `CREATE INDEX CONCURRENTLY` などトランザクション内で実行できない文は、書き込みモードで1文だけ投げたときに限りトランザクション外で実行する |

**できること** — スキーマ / テーブル / 列の一覧、先頭行の閲覧、`CREATE TABLE` 相当の DDL 表示、
複数文の実行（`;` 区切りで文ごとに結果タブ）、エラーの位置表示、CSV 書き出し、実行履歴、
入力補完（Ctrl+Space）、実行中のクエリの中止。

**キー操作** — `Ctrl+Enter` 実行（選択範囲があればその部分だけ）、`Ctrl+Space` 補完、
`Tab` / `Shift+Tab` 字下げ、`Ctrl+/` コメントの切り替え。

## 3. データ保存先

- `settings.json`: ギルドごとの Bot 設定
- `data/.admin_session_secret`: 管理UI セッション署名キー（`ADMIN_FLASK_SECRET_KEY` 未設定時に初回起動で自動生成）
- `data/logs/bot.log`: Discord Bot のログ（最大 1MB × 3世代）
- `data/logs/admin.log`: 管理 UI のログ（最大 1MB × 3世代）
- `data/admin_monitor/`: 監視のハートビートとインシデント記録
- `data/_dev_signals/`: 開発者パネルから Bot へ渡す実行シグナル
- `data/djaudio_cache`: DJAudio の一時 MP3 キャッシュ
- `migrations/` + DB（`POSTGRES_DB`）: Web トラッカーの永続データ
- DB（`USER_STATE_POSTGRES_DB`）: ユーザー状態監査データ

> `data/` の保存先は環境変数 `SETTINGS_DIR` で変更できます。Docker 運用時は Bot と管理 UI で
> ボリュームを共有することで、ログビューアと開発者パネルのシグナルが機能します。

## 4. ワーカー数について

`ADMIN_WORKERS` の既定は **1** です。メトリクス（TPS）・監視スレッド・レート制限は
いずれもプロセスローカルなので、2 以上にすると表示値が実態とズレ、監視スレッドが
多重に走ります。複数ワーカー/複数台で運用する場合は
`ADMIN_LIMITER_STORAGE_URI` に Redis を指定してください。
