# voice-check

serenity + songbird の Bot が、DAVE（Discord の音声のエンドツーエンド暗号化）が
必須の VC で、**相手に音を届けられるか**を人の耳で確かめる道具です。

## なぜ要るか

Discord は 2026-03-02 からボットにも DAVE を必須にしました。暗号化されていない
音声は、受け取った端末が黙って捨てます。

songbird には、DAVE の準備ができる前に送った音声が暗号化されずに出ていき、
相手に捨てられるという未解決の報告があります（[songbird #310](https://github.com/serenity-rs/songbird/issues/310)）。
このとき **Bot 側のログには何も出ません。** songbird は DAVE の鍵交換に成功しても
ログを出さず、失敗したときだけ警告を出します（`driver/tasks/ws.rs`）。

つまり、ログやテストからは「届いた」と言えません。人が VC で聞くしかないので、
そのための最小の Bot を用意しました。

## いつ使うか

- serenity・songbird・davey のどれかを上げるとき（**本番へ出す前に必ず**）
- Rust の Bot を初めて本番へ出す前

## 用意するもの

1. **試験用の Discord アプリ。本番の Bot のトークンは使わないこと。**
   - 動いている本番の Bot と接続がぶつかります。
   - この道具は、2 つ以上のサーバーに入っている Bot では起動を拒みます（取り違えの保険）。
2. 試験用アプリを招待した、VC のある試験用サーバー。
   - 招待のスコープ: `bot` と `applications.commands`
   - 権限: チャンネルを見る・接続・発言
3. Docker が動く環境（手元なら WSL）。

## 手順

設定ファイル（既定は `$HOME/.sycs-voice-check.env`）に 2 行を書きます。

```
DISCORD_BOT_TOKEN=<試験用アプリのトークン>
TEST_GUILD_ID=<試験用サーバーの ID>
```

起動します。初回は依存の取得とビルドで数分かかります。

```sh
sh rust/tools/voice-check/run.sh
```

ログに `/voice-test を登録した` が出たら、試験用サーバーの VC に入り、次の順で
打ちます。それぞれ「低・中・高」の 3 回のうち何回聞こえたかを数えます。

| 打つもの | 見ていること |
|---|---|
| `/voice-test` | VC に入った直後の音が捨てられないか（#310 がいちばん出やすい） |
| `/voice-test delay_ms:3000` | 落ち着いてから鳴らしても届くか（比較用） |
| `/voice-test delay_ms:10000` を打ち、待っている間にもう 1 人が VC に入る | 参加者が増えて鍵が入れ替わったあとも届くか |

**全部 3 回聞こえたら合格です。** 最初の 1 回だけ欠けるなら #310 の症状です。

終わったら Ctrl+C で止め、試験用アプリのトークンを無効化（Reset Token）します。

## これまでの結果

| 日付 | serenity | songbird | davey | Rust | 直後 | 3 秒後 | 参加者が増えたあと | DAVE の警告・エラー |
|---|---|---|---|---|---|---|---|---|
| 2026-11-25 | 0.12.5 | 0.6.1 | 0.1.5 | 1.100.0 | 3/3 | 3/3 | 全員 3/3 | 0 件 |

2026-11-25 の試験は、E2EE が有効な VC で行いました。#310 の 3 つの症状のうち、
送信側の「入ってすぐの音が捨てられる」は再現しませんでした。残りの 2 つは
受信側の症状で、録音機能を外した今の Bot には関係しません。

まだ確かめていないこと:

- 読み上げの最中に参加者が入れ替わる場面
- 長時間つなぎっぱなしにした場面

Rust の Bot を本番へ出す前に、ここを確かめてから表に足すこと。
